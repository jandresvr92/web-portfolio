# AGENTS.md

Isometric portfolio built with TanStack Start (React 19, **plain JavaScript, no TypeScript**), Tailwind CSS 3 and Framer Motion. It deploys to Vercel through Nitro. `README.md` explains the architecture, the folder map and how to add content; this file holds the rules every change must follow, whoever makes it.

## Workflow

- One branch per change, opened as a pull request against `main`. Never commit to `main` directly.
- Before you finish, run `npm run check` (lint, content tests, build). CI runs the same steps on every pull request; a red check means the change is not done.
- Then open the site with `npm run dev` and click through the nodes on desktop and at mobile width (375 px). Every pull request also gets a Vercel preview.
- Keep the diff to what was asked. If you notice something else worth fixing, say so instead of fixing it in the same change.

## Code conventions

- Write JS/JSX only. `src/routeTree.gen.ts` is generated by the router plugin on every dev/build run; never edit or commit it.
- Import with the `@/` alias (`@/lib/utils` → `src/lib/utils`). It is defined in `vite.config.js`, `vitest.config.js` and `jsconfig.json`; keep them in sync.
- Pages are server-rendered, so the server and the first client render must match. Read `window`, `document` and storage only in effects or handlers, and never format dates or numbers with `Intl` or `toLocale*` in render (month names come from the dictionaries).
- `vite.config.js` plugin order is `tanstackStart()`, `nitro()`, `react()`, as in the TanStack Start hosting guide.
- `nitro` is pinned to an exact release candidate (v3 has no stable release yet). Upgrade it on purpose, and check `npm run build` and `NITRO_PRESET=vercel npm run build` afterwards.
- Tailwind only keeps class names it can read in the source: write every class in full, never build one from a variable (`text-${color}-300` is lost). Per-node colors live in `nodeTheme.js` and `director/directoryData.js` for that reason.

## Content

- Visible copy comes in three languages (`en`, `es`, `de`). Shared strings live in `src/lib/i18n/dictionaries.js`. Each node keeps its structure (ids, links, dates, images) once in `*Data.js` and its text per language in `*Copy.js`, keyed by the same ids. When you add a string, add it in all three; `npm test` fails if a language is missing one.
- Each `*Data.js` explains how to add an entry. The layout limits (6 hobbies, 4 blades per stack tab, tag counts, text lengths) are enforced by `tests/content.test.js`; if one fails, shorten or swap the content instead of raising the limit. A limit only changes together with the component that draws it.
- Counts, years and date labels are computed from the data: never write them into the copy. Use `{count}`, `{years}` or `{n}` placeholders, filled with `fill()` from `src/lib/i18n/format.js`.
- The hidden profile summary for search engines (`components/seo/ProfileSummary.jsx`) is built from the same data and copy, so it updates on its own. Do not add text there that the site does not show.
- Name, role, domain and profile links live in `src/lib/site.js`. Change them there; the meta tags, the JSON-LD and the CV and share-image builds read them.

## CV and share image

They are generated, never edited by hand:

| File | Source | Command |
| --- | --- | --- |
| `public/cv/CV_Jaime_Andres_Velez_Rojas.pdf` | `tools/cv/cv.html` | `npm run cv:build` |
| `public/images/og/og-image.jpg` (1200×630) | `tools/og/og.html` | `npm run og:build` |

`{{VALUES}}` in the sources come from `src/lib/site.js`. When the role, jobs, projects or skills change on the site, update `tools/cv/cv.html` (and `tools/og/og.html` if its tags change) and rebuild, so the CV, the share card and the site tell the same story. The script drives the Chrome or Edge already installed; set `CHROME_PATH` if it is not found.

## Static files

Static files go in `public/images/` or `public/cv/`, never `public/assets/`: that path is reserved for Vite's hashed bundles and cached immutably on Vercel. The only exceptions are the site icons (`favicon.svg`, `favicon.ico`, `apple-touch-icon.png`), `robots.txt` and `sitemap.xml`, which stay at the root of `public/` because browsers and crawlers request them there. `robots.txt` and `sitemap.xml` repeat `SITE_URL` from `src/lib/site.js`; the tests check they match. Images are WebP (project screenshots 1280×720); the share image is JPEG for compatibility.

## Design rules

The site is a dark terminal on an isometric grid. Keep new UI inside that language; do not introduce new fonts, color families, radii or shadow styles.

**Palette**

- Background `zinc-950` (`#09090b`); text `zinc-200` (body), `zinc-100` (headings), `zinc-400`/`zinc-500` (secondary); borders `gray-800` / `zinc-800`.
- Brand accent: neon amber, the `--neon` CSS variable (`text-neon`, `border-neon/40`…), used for the brand and global focus.
- One accent per node, used for its panel, cards and focus ring, and nowhere else:

  | Node | Map and mobile (`nodeTheme.js`) | Panel classes |
  | --- | --- | --- |
  | Profile | `cyan` | `cyan-300/400/500` |
  | Projects | `purple` | `purple-300/400/500` |
  | Stack | `orange` | `orange-300/400/500` |
  | Experience | `lime` | `green-400/500` |
  | Hobbies | `amber` | `yellow-300/400` |

**Typography**

- One family: JetBrains Mono (`font-mono`) everywhere.
- Panel header: subtitle `text-[9px] uppercase tracking-[0.3em]` in the accent at 60 %; title `text-[22px] uppercase tracking-[0.14em]` in the accent 300.
- Body `text-[11.5px]`–`text-[12.5px]` with `leading-relaxed`; small labels `text-[10px] uppercase` with `tracking-[0.12em]`–`tracking-[0.2em]`.
- Status line closing a panel: `border-t border-gray-800 pt-3 text-[10px] uppercase tracking-[0.12em]` in the accent at 70 %.
- Phones: panels shared with desktop raise their sizes inside the mobile sheet with the `sheet:` variant (`text-[10px] sheet:text-[12px]`); text in the sheet is never smaller than 12 px.
- Terminal flavor in labels: uppercase, `//` separators, `[ BRACKETS ]`, a trailing `_`. Keep it in labels and system lines; body text stays in sentence case.

**Shapes and depth**

- Square or nearly square corners: `rounded-sm` at most (`rounded-full` only for dots and the avatar).
- 1 px borders; glow comes from the node accent (`shadow-[0_0_15px_…]`, `drop-shadow`), never from new colors.
- Dim inactive elements with `brightness`, not `opacity`, when something sits behind them (the map's rooms hide the cables).

**Motion**

- Entrances: Framer Motion, 0.2–0.45 s, `easeOut`, staggered by about 0.06–0.09 s per item; springs (stiffness about 200–320) for sheets and pressable cards.
- Every looping or ambient animation must stop under `prefers-reduced-motion`: add `motion-reduce:animate-none` and list its class in the reduced-motion block of `src/index.css`.

**Accessibility**

- Interactive elements are real buttons or links with a visible keyboard focus state (`focus-visible` outline in the node accent, or the same highlight as hover).
- Decorative images get `alt=""`; meaningful ones get a description.
- Check the page at 375 px: no horizontal scroll, no truncated titles.
